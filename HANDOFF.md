# Jersey QC Scanner — hand-off (16 Oct 2026)

Read this first in a new chat. It is the state of the project, how to run and test it, and what is next.

## What this is

A React/Vite web app for Athletic Knit's finishing floor. An overhead camera photographs the back of a jersey; Claude Haiku reads the name and number; the app matches it against the order's roster and tells the operator the size and bin. Three co-op students: the user (aerospace) and another aerospace co-op own this app; a comp-sci co-op is building the roster/order server. Phases: **1 rostering (this work)** → 2 reporting → 3 packing (weigh scale) → 5 supervisor view.

## How to run

- **Floor / LAN:** double-click `Start Jersey QC.bat` (HTTPS on 5173, bound to all interfaces, self-signed cert; other PCs click Advanced → Proceed once). The console window IS the server. Other PCs still need an inbound firewall rule for TCP 5173 (Domain profile) — never added yet; must be run as Administrator by a person.
- **Testing in Claude's browser pane:** `npx vite --config vite.config.diag.js` → plain HTTP on 5174 (the pane cannot accept the self-signed cert). `vite.config.diag.js` is gitignored; it is the same as `vite.config.js` minus `basicSsl()`.
- API key: `.env.local` → `VITE_CLAUDE_API_KEY` (present, confirmed working, ~$0.001/jersey on Haiku 4.5). Never print it; `/src/App.jsx` served by the dev server contains it (known issue C6).
- Role PINs: defaults `1111/2222/3333/9999` (inspector/packer/supervisor/admin) in `src/config.js`; override with `VITE_PIN_*` in `.env.local`. Soft gate only.
- Hub state: `data/hub.json` (gitignored).

## Code map

- `src/App.jsx` — the whole UI: SignInModal, OrderSetupModal (file or supervisor roster), ManualEntryForm, SupervisorPanel, ScanOverlay (option-list model), ResultCard, SettingsPanel, BinSetupModal, RosterCompleteModal, App.
- `src/lib/match.js` — `findMatches` (exact / duplicate / pick / close / none), sleeve-merge guard, name-overrides-number, one-digit fuzzy; `isDone` = pass or manual.
- `src/lib/roster.js` — CSV/Excel parsing (BOM, quotes, delimiters, aliases, header/sheet detection), size merge, bins (case-folded, pinned), extra columns.
- `src/lib/motion.js` — hands-free gate: lift → settle → texture → place → scan. Thresholds measured on the 32×18 sample: identical 0.0, one digit changed 3.7, nudged 8.5, different player 12.4, hand 29.6, bare table 60 → `sameBelow 2.5`, `changeAt 10`, `minTexture 5`. Re-baselines on a nudge. Logs phases to the console as `[hands-free] …`.
- `src/lib/vision.js` — sleeve-aware prompt, 25 s timeout, one retry on network/429/5xx, string coercion.
- `src/lib/persist.js` — session (resume on reload), settings (v2), sign-in. `src/lib/export.js` — CSV quoting, local dates, statuses incl. MANUAL. `src/lib/audio.js`, `src/lib/hub.js`.
- `hub-plugin.js` — Vite plugin: `/api/hub/stations` (POST snapshot every 5 s from each station), `/api/hub/rosters` (supervisor sends, stations pick). Same shape for the comp-sci co-op's server to adopt.
- `src/config.js` — model, CHECKLIST chips, REASONS (routing), ROLES/PINs, DEFAULT_SETTINGS (keys: B scan, Enter select, A/arrows navigate, R retry; rotation; camera; autoScan).

## Testing approach that works

Claude's browser pane has no camera; `tools/browser-harness.js` fakes one (a canvas streamed via `captureStream`) and a controllable network, and includes the 100-jersey driver. Paste it into the console at `http://localhost:5174` after signing in and starting an order — or load it without pasting: `(0, eval)(await fetch('/tools/browser-harness.js').then(r => r.text()))` (no `?raw`: Vite wraps that in `export default`). Install it before pressing Start Camera. Vite serves the harness through its pipeline, so editing the harness file reloads the page and drops the install.

**Several stations in one browser** (16 Oct): a station's id is stored once per browser, so three tabs would report as one station. `?station=line2` in the URL names the station instead (`src/lib/hub.js`), which is also the way to give a floor PC a fixed label on its shortcut. Demo recipe: open `http://localhost:5174/?station=line1` … `line3`, sign each tab in as a different inspector (the sign-in is shared storage, but each tab keeps its own name in memory), start an order in each with the harness loaded, drive scans with `B` from a loop in each tab, and open the Supervisor view in a fourth tab — three live cards, counts moving every 4 s. Hidden tabs throttle timers, so drive them with `B`, not hands-free.

**W = Enter by hand** (19 Oct): a fifth configurable key (`byHandKey`, default `W`) opens the by-hand form directly from any red screen or pick list, the way `R` goes straight to retry. Badge on the button, in the hint line and the key legend; Settings checks it differs from the other on-screen keys. Typed matches pass as MANUAL (supervisor sign-off). **A typed jersey that is not on the roster is no longer added** (19 Oct, user's decision: the roster is the order): it is logged as FLAGGED with `match.offRoster`, the station shows GO TO SUPERVISOR ("nothing was added — check against the order paper"), the Flag pill and the completion modal count it, and the supervisor gets the red toast at once. The pick-list escape reads "None of these — #88 Zielinski is not on the roster" (W). Rows with `added: "operator"` from before 19 Oct are still rendered if a saved session has them. `formatKey` now tolerates a missing key, because a hot reload with stale settings crashed the page once.

**Break-it suite** (19 Oct, `tools/break-it.js`, run on the 5174 test server with the fake camera; load the harness, open the harness roster, start the camera, then `__breakIt()`; results in `window.__breakItResults`): 22 scripted scenarios. **App: every scenario passed** once the driver's own mistakes were corrected by hand — duplicates, sleeve merge 777, crumpled read with tip, right-name-wrong-number never green, nameless shared number, near miss 88 → W → GO TO SUPERVISOR with nothing added, COULD NOT READ → W → MANUAL, typed name + wrong number → typed list → green with the typed note, defect reason, free-text reason, network drop and 429 with automatic retry, hand pull-back, nudge, dialog pauses hands-free and re-arms, pause/resume hands-free with B still working, Change operator keeps everything, held key fires once, mid-order roster banner, dead camera refused and recovered, reload → Resume with log and counts intact, and on the supervisor side toasts for every flag (three at once arrived together), backlog banner, carried items, Remove only on stale cards. Driver lessons for whoever edits the suite: an "empty read" must still draw text on the jersey (a blank cloth is the table to the gate, correctly); pull-back must redraw the LAST scanned jersey; form inputs must be read from the overlay (`ov().querySelectorAll('input')`), because the page's first input is the header's order-number box — writing into it renamed the order mid-run, which is how the carried-items duplicate was found and fixed (key no longer includes the order). Two observations, not bugs: a jersey swapped while a dialog is open is not scanned on close when the swap is below the change threshold (lift and re-place, or B); and the supervisor view can only be closed by its Back button — if alerts seem to vanish, the view was closed.

**Result screen in the right half; un-check a jersey** (19 Oct): on screens ≥ 1000 px the green/yellow/red screen is drawn inside the right column (`embedded` ScanOverlay, `position: absolute`) so the camera stays in view at full size; the live-camera window is not drawn there. Narrow screens keep the full-screen overlay with the window. **Un-check**: "↶ Undo — scan again" on the last-jersey line under the camera, and "Un-check — scan again" in the roster table's Mark dropdown for any passed, by-hand or flagged row. One confirm ("goes back to Remaining and must be scanned again"); the row returns to unscanned, a log line with status `undo` says who and when, earlier lines stay, open flag/by-hand lines for that row get a resolution so the supervisor's list drops them, and the hub's day tally goes down by one (same-order deltas may now be negative).

**A station is on the board from sign-in** (19 Oct): the station reports to the hub as soon as an inspector or packer signs in, with no order ("Waiting for an order" card, "(waiting for an order)" in the supervisor's Send-to list), so the supervisor can send the first order of the day to a named station. The order screen re-checks the hub every 5 s and says "Waiting for the supervisor to send an order — it will appear here by itself"; a sent order appeared in 3 s in the test. A supervisor signed in on a laptop without an order does not report (no card for the laptop).

Unit test added. The roster sheet of an export is therefore safe to send back out as a roster.

**Send a roster to one station** (19 Oct): the supervisor's form has a "Send to" choice — any station (first to take it) or one station from the cards. The roster carries `forStation` (a station id); stations list only rosters sent to them or to anyone, both on the order screen ("for this station" tag) and in the mid-order banner; the waiting list shows "→ Line 2" or "any station". Verified with two stations: Line 2 saw both, Line 1 saw only the open one. **Live camera on the result screens** (19 Oct): every green/yellow/red screen shows a live window bottom-right (`LivePreview`, a second `<video>` on the same stream, mount rotation applied) so the operator lines up the next jersey while confirming; the read thumbnail moved bottom-left. **Hands-free stops when the order is done, and can be paused** (19 Oct, from the real test: after the 35th jersey the gate kept re-arming and read the empty table as COULD NOT READ every few seconds). `handsFree = autoScan && !paused && remaining > 0` gates the interval, `armAutoScan` and `closeDialog`; the badge reads "Order done — hands-free off". A button beside SCAN is always visible and has three states: hands-free off in Settings → "▶ Hands-free" turns it on (and saves the setting); running → "⏸ Pause scan" disarms the gate but keeps the camera on and B working ("Hands-free paused — B to scan"); paused → "▶ Hands-free" resumes. **Free-text defect reason** (19 Oct, from the first real-fabric test): "Something else — type it" at the end of the reason list opens a one-line box; the text becomes the reason (route "Supervisor decides"), the jersey goes to GO TO SUPERVISOR, and the supervisor's toast and card show the typed words. G read as C is the same font problem; the hints help, the near-miss list and the number carry the rest. Script: `scratchpad/prompt-compare.mjs` (reads the key from `.env.local`, never prints it) — the seed of the planned evidence loop. **After a `src/lib` change, hard-reload open station pages.**

## Tooling quirks on this machine

Write/Edit tools decode `\uXXXX` in file content into the literal character — never put `\u` escapes in source (use `String.fromCharCode(0xfeff)`, `/\p{M}/gu`). Bash heredocs containing single quotes fail here; write files with the Write tool. GNU sed treats `\u` as uppercase-next.
