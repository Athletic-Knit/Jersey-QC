# Jersey QC Scanner

## What this project does

A React/Vite web app for quality-control scanning of sports jerseys in a manufacturing environment. An operator photographs each jersey with their device camera; Claude Haiku reads the player name and number from the image and matches it against an uploaded roster.

**Workflow:**
1. Operator enters their name, order number, and uploads a roster file (CSV/TSV or Excel). The jersey type (ECHL / ECHL replica, stitched; Sublimated, printed — `JERSEY_TYPES` in config.js) is picked on the station's setup form or the supervisor's send-roster form: the flag reasons follow it (`reasonsFor`), so an ECHL order is never offered "Sublimation error"; with no type set the station offers every reason from both lists (`ALL_REASONS_MENU`). The Mark menu on an unscanned roster row offers Missing only (Short-shipped was removed 9 Nov 2026; the `short` status is still read for old sessions).
2. Boxes (the code and this file's older notes say "bin"; on the floor, on every screen and on every label it is a box, 12 Nov 2026). A box's name is two numbers: `5.2` is the second box of sort 5 (a team, a size, or the whole order). The first number never changes for a team or size; the second counts its boxes as they fill (`boxParts`, `binOrder`, `nextBinNumber` in roster.js; bin ids are strings, an older saved order's plain numbers still read). When an order starts, the "Set out N boxes" screen (every order, also one team) lists each team or size with how many boxes the box model expects it to fill (`boxPlan` in App.jsx) and one 2 × 1 in label per expected box prints by itself as the screen opens (`boxAuto` → `autoPrint`; BOX 5.1, 5.2, 5.3; `binLabels(…, { boxes })`; the button prints them again; opened later from the Boxes dialog nothing prints until the button), which the operator sticks inside the open boxes lined up at the station. Box full closes 5.1, prints the list of what is in it (the label that goes on the taped box) and the team carries on in 5.2; the next box's label prints then only if it was not printed before (`boxLabelled`, saved in the session). The Boxes dialog's "Box labels" button opens the set-out screen again. The owner will supply a weight regression (all 9 sizes weighed) to replace the box model's estimates.
   Bins, as first built: the supervisor chooses on the send-roster form (and the station on its setup form) whether the order is sorted by team, by size, or not at all (`BIN_BY`, `binBy` on the hub roster). Every order has at least one bin, because packing boxes by the bin: one team or size is Bin 1, and an order that is not sorted (or has no team or size to sort by) is one bin for the whole order (`{ "*": 1, __by: "all" }`, `ALL_KEY`). With more than one team or size a bin screen appears (Bin 1 = Navy, Bin 2 = Red; or Bin 1 = Y-M, Bin 2 = A-L …). A size map carries `__by: "size"` (`binFieldOf`), a team map is flat; `binFor(binMap, row)` takes the roster row.
3. Camera feed is shown; operator presses a configurable key (default: `B`) to scan a jersey
4. Claude Haiku extracts name + number from the photo via the Anthropic API
5. Match result shows as a full-screen overlay:
   - **Green** = exact match → confirm with `B`, or edit with `A`
   - **Yellow** = multiple candidates or close match → pick from list
   - **Red** = not found or API error → flag and continue
6. Flagged items appear in the log and can be resolved (Accept / Reject / Note)
7. When all roster entries are scanned, a completion modal offers Excel export
8. "🏁 Finish order" (header, and on the completion modal) shows a confirm with passed / open / not-scanned counts; Enter or ✓ prints the list of every open box and then STAYS on an "Order N is done" screen (`FinishedModal`, `finished`; owner, 12 Nov 2026): "Print the box lists again", "Print something else…" (the Print menu), "New order →" and "Back to this order". Only "New order" clears the order, removes the roster from the hub (no station is offered it again) and returns the station to "waiting for an order" (the hub keeps the order's record and sheets); until then the order is still open and saved, so a reload offers it again. No key acts on that screen (the pedal must not start a new order). Esc on the confirm keeps going
   Print menu ("🖨 Print" in the header, on the order-setup screen and on the done screen; `PrintModal`, `src/lib/printjobs.js`): everything the label printer prints, on request — every box label, every box list, both; one box's label, list or both; a jersey's sticker (search by number or name, or all); a flag's ticket (or all). It opens on the order on the station; "Another order" finds an order done before by its number in the hub's ledger (`GET /api/hub/orders?q=`, exact number first, a part of the number from 3 characters, newest run first, no photos) and prints from that record (`packFromRecord`). It always prints on the printer of the station it is used at. A reprinted sticker carries the box the jersey is IN (`binOfRow`), a closed one too.
9. One station per order: starting a sent roster takes it on the hub (`POST /rosters/:id/take`, `takenBy`); other stations see it greyed "In progress on Station 1" and get a 409 if they race; the board's "Rosters sent" list shows who has it with Release / Remove. Each start of an order on a station is a run (`orderRun`, saved in the session, reported in the snapshot and on events); the hub's ledger keeps one order record per run (`station|order|run`), so an order started again by mistake does not overwrite the finished one

## Tech stack

- React 19, Vite 8 (ESM)
- Single component file: `src/App.jsx` (~900+ lines, all inline styles, dark GitHub-like theme)
- Type and far-view scale: `src/index.css` ships two self-hosted typefaces (`@fontsource`): Atkinson Hyperlegible for UI text (`FONT_UI` in App.jsx) and Barlow Condensed for the big numerals — jersey number, size, bin, the counters (`FONT_DISPLAY`). The stations are 27" monitors read from 4–5 ft, so `#root` gets `zoom: 1.3` at ≥1600×800 and `1.7` at ≥2300×1200; everything is laid out in the smaller logical viewport and enlarged. Because of the zoom, full-height boxes use `100%`, not `100vh`.
- SheetJS loaded from CDN (`https://cdnjs.cloudflare.com/ajax/libs/xlsx/0.18.5/xlsx.full.min.js`) for Excel read/write
- Anthropic API (Claude Haiku 5.5 `claude-haiku-5-5`, thinking off, low effort, 800 px frame; overrides below) called **directly from the browser** via `fetch("/api/anthropic/v1/messages")` — requires a Vite dev proxy or a hosting proxy in production

## Running locally

```bash
npm install
npm run dev
```

The dev server starts at `http://localhost:5173`.

> **Note:** The Anthropic API is called via `/api/anthropic/...`. In dev, Vite must proxy this path to `https://api.anthropic.com`. Add a proxy in `vite.config.js` if not already present:
> ```js
> server: {
>   proxy: {
>     '/api/anthropic': {
>       target: 'https://api.anthropic.com',
>       changeOrigin: true,
>       rewrite: path => path.replace(/^\/api\/anthropic/, ''),
>     }
>   }
> }
> ```

## Roster file format

Supported: `.csv`, `.tsv`, `.txt`, `.xlsx`, `.xls`

Expected columns (case-insensitive, auto-detected):
- `name` — player name
- `number` — jersey number
- `team` — team name (optional, used for bin assignment)
- `size` — size (optional)
- `size range` + `size` — auto-merged into `A-XS` / `Y-M` style combined size
- `order` / `order number` / `PO` / `job` (optional) — fills the order number at setup; a title row above the header such as `Order 55555` works too. Not kept as a roster column (`orderNumberOf()` in roster.js).

## Key architecture notes

- All state lives in the top-level `App` component; no external state management
- `findMatches()` handles exact, conflict (same number, different players), close/fuzzy matching
- Keyboard shortcuts (scan/confirm/cancel keys) are fully configurable via Settings panel
- Designed for use with a barcode scanner or foot pedal mapped to keyboard keys (voice commands were removed on 5 Nov 2026)
- Audio feedback: ascending tone = pass, descending = flag, short beep = scan trigger, two flat blips = retry (the scan dropped, nothing recorded)
- Retry pedal (`retryKey`, default `R`): on a green screen it only lays "That's the retry pedal — B confirms" over the screen for 5 s and the green stays (a retry there looked exactly like a confirm and a jersey went in the bin unchecked, 5 Nov 2026); the Retry button on a green is a mouse click only (`mouseOnly`: the arrows skip it, B never runs it). A real retry (red, yellow, duplicate) keeps an amber "Scanned again · #N is NOT checked — no sticker, no bin" strip on the camera screen (`retried`) until the next scan. Floor rule: no sticker, no bin.
- Hands-free (`src/lib/motion.js`): after a confirm the gate waits for the picture to change and then sit still (~0.8 s); a still picture that is neither the jersey just scanned nor the empty table scans. Works for one jersey placed at a time and for a stack lifted jersey by jersey. After a confirm the gate holds for `autoScanDelay` seconds (Settings, default 3) before it may fire, so the operator can put the old jersey away and reach for the next. The empty table is learned, not guessed: the read returns `jersey_present`, and a read with no name and no number (an empty table, or fabric with no lettering in view) never shows a result screen: hands-free is silent, a B press shows "No jersey in view" for a moment; either way it teaches the gate the table and re-arms, with nothing in the log. A read with any name or number in it is never "no jersey", whatever the flag says.
- Turned jerseys: the read returns `orientation`; when it is not `upright` the app turns the frame (`rotateDataUrl`) and reads again, and the two reads reconcile (`src/lib/vigilance.js`). A nameless 6/9, 18/81, 66/99 on a turned jersey with the twin number open on the roster is a question (`rotated180` in match.js).
- Self-check after a mistake (`src/lib/vigilance.js`): when the operator corrects the app (a green typed over, a list without the jersey, a "could not read" then typed, a pass un-checked) the next 5 jerseys are read twice and must agree before a green; another mistake restarts the 5. A "Double-checking · N to go" pill shows in the header. The counter lives in the saved session (`vigil`). The operator simulation runs it too (`SIM_VIGIL=0` to compare).
- Operator inspection regime (`createInspection` in `src/lib/vigilance.js`): full inspection of the first 5 jerseys of an order and of the next 5 after any defect the operator flags; otherwise a quick look with a full spot check after every 10 clean. Shown as a header pill and a banner on the green screen (check pills only during a full inspection); saved in the session (`inspect`). Independent of the app's own double-check.
- Lone digits: the roster hint asks the model to flag a hidden second digit only on evidence (a fold, crease, sleeve, hand, tag or picture edge beside the digit), and an exact name + number match is green whatever the camera says about the digit unless the same name is open on a hidden-digit row.
- Damage photo: the flag photo (`photo`, the scan cropped to the jersey) only ever shows the back. On the GO TO SUPERVISOR screen a "Photo of the damage" button (primary for defect reasons, second to Continue for "wrong name, number or team" and "not on the roster") runs a 3-2-1 with a tick a second and a shutter, then keeps the live frame uncropped on the log entry as `damagePhotos[]`; Retake drops the last, Take another adds. B or the pedal triggers it too. Both photos go to the hub (the plugin keeps them once seen), the supervisor board and the Excel damage report ("Damage photo" column, more columns when a jersey has several); the saved-session photo budget counts them.
- Supervisor board weighting (`routeOfReason` / `severityOf` in config.js): every open item carries a tag from the route its reason implies (REMAKE over DECORATION / STITCHER over CLEANING / CHECK ORDER over SIGN OFF / DECIDE), the Needs-you list shows the three that weigh most, open before resolved. A station silent for over 2 hours (`GONE_MS`) steps back into one "Not reporting" strip and its old items leave the header count and the backlog banner. "📺 Wall" (or `?view=wall`) is one row per station in letters for a TV, sized in container-query units because of the page zoom; click or Esc returns. The board sends no notifications at all (no pop-ups, no desktop notifications, no tone, by the owner's decision on 4 Nov 2026): the header count and the cards' red lists are the whole story. A supervisor's sign-in is the board and nothing else: no station behind it, no scanning, no resume; its header button is Sign out. Look-back: the hub keeps 90 days of ledger (`pruneLedger` in hub-plugin.js), photos only on the newest 14 (`photosPruned: true` on the event afterwards); the board's Orders list has a day picker and the order view, order sheet, day sheet and damage report follow it. Station cards are always now.
- Roster table at the station: a Sort by row (Size · Status · Name · Number · Team · Bin, `sortRoster` / `ROSTER_SORTS` in roster.js); size (the rack order) by default; Status puts the done ones on top, with a "Done on top / To do on top" toggle (`doneFirst`). "Show" filters the table to one size and/or one team (`rosterChoices`). The Mark menu of a passed or by-hand row offers "🚩 Flag / damage" (`flagRow` → the reasons menu, like Flag it on the last pass) as well as Un-check. The order's History button sits bottom-left under the last pass, not in the header.
- Stickers (`src/lib/labels.js`, `tools/print-raw.ps1`): every passed jersey (a green confirmed, a pick from the list, a by-hand pass; never a flag) prints a 1 × 0.5 in sticker on a Zebra ZD411 (203 dpi, ZPL): BIN and the number in a left column, TEAM or SIZE and its value on the right, the order number small under it (`jerseyLabel` / `jerseyLabelZPL`). The inspector folds the jersey and sticks it on; the packer stacks by bin. The station posts it to the hub (`POST /api/hub/print { labels, kind: "jersey", station }`), which builds the ZPL and sends it raw to the Windows queue for that station (`JERSEY_PRINTER_<STATION>`, else `JERSEY_PRINTER`, else the first Zebra queue on the server PC); the printer is driven from the server PC, so a Zebra at a station is shared from the station PC and named in `.env.local`. Fire-and-forget on `lastConfirmed` (`stickerPrinted` ref, so once per pass and never on a resumed order); the Last passed strip shows "Sticker printed" / "No label printer for this station" with Reprint; Settings → Label printer turns it off (`stickers`). The Bin setup modal's "🖨 Print bin labels" prints one bin label per bin on request (`binLabels` / `binLabelZPL`), nothing automatic; they go on the 2 × 1 in roll (kind `"binticket"`, the same label as a bin opened when another was full; on the sticker roll's layout the text filled a corner of the label, 10 Nov 2026): "BIN 3" at half the label's height, the team or size under it, a small footer (order number, by team / by size; no jersey count, as nobody knows how many go in before it is full). Printing starts 2 mm below the label's top edge (`top` in `labelSize`): the ZD411 cut the first line in half otherwise.
- Flag tickets (`flagLabel` / `flagLabelZPL`, kind `"flag"` on the print route): every flag (a reason chosen, "not on the roster", a duplicate, a flag on a passed jersey) prints the mirror of the sticker on a **2 × 1 in** label (`DEFAULT_FLAG_LABEL_SIZE`, `JERSEY_FLAG_LABEL_SIZE`): a solid black column on the left with FLAG, the number and the name in white (so the packer never boxes it), and on the right the route tag from `severityOf` (STITCHER, REMAKE, DECORATION …), the reason on up to three lines, team · size · bin, and order · station · time. The layout is in fractions of the label, so it also comes out on the sticker roll. On the 2 × 1 in roll the text starts 2 mm in from the left (the ZD411 cuts that much), while the black column itself runs off the top and left edges, so no white strip is left around it (10 Nov 2026). The ticket starts 4 dots (0.5 mm) higher (`FLAG_LIFT`, `^LT-4`) so the black reaches the top edge; the texts are laid out 4 dots lower and sit where they did. Not more than 4: the printer prints a window exactly one label long, so each dot of lift is a dot lost at the bottom (6 left a white line there). The printer keeps `^LT`, so every other label sets `^LT0`. The hub sends it to the flag printer (`JERSEY_FLAG_PRINTER_<STATION>`, else `JERSEY_FLAG_PRINTER`), else to the station's sticker printer (`ticketPrinter` in hub-plugin.js). Printed once per log entry from the newest log entry (`ticketPrinted` ref; a resumed order counts its last entry as printed); the GO TO SUPERVISOR screen shows "Flag ticket printed" / "No label printer" with Reprint; its own switch under Settings → Label printer (`flagTickets`), apart from the stickers'. labels.js runs on the hub as well, so it never imports config.js: the station passes the tag in.
- Full bins and bin lists (`closeBin` / `binOfRow` / `binContents` in roster.js, `binListLabels` / `binListZPL` in labels.js): the bin map only says which bin is OPEN for a team or size. "📦 Bin full" (beside History, when the order has bins) lists the open bins with what is in each; closing one keeps `{ bin, key, label, ids, closedAt }` in `closedBins` (saved in the session), moves the team or size to its next box (5.1 → 5.2, `nextBinNumber`; a first number is never handed to another team or size, also not by `buildBinMap`'s `taken`), and prints on the 2 × 1 in roll: the list of what was in the bin (kind `"binlist"`) and the new bin's label (kind `"binticket"`). A done row in a closed bin stays in it (`binOf` in App.jsx goes through `binOfRow`); an un-check takes it out (`dropFromClosed`). The list is every passed or by-hand jersey as `23-JAMES-AXL` (number, name, size without its hyphen), fourteen a label in two columns of seven read down the left then down the right, in jersey-number order, with no header at all on those labels; one count label goes with them ("BOX 5.1", "24 pcs", the team or size and the order small under it; `title: true`, `binCountZPL`). `binListLabels` returns them in the order they print: the last page of rows first and the count label last, so the strip off the printer reads count label, page 1, page 2 (owner, 12 Nov 2026). The box size is not printed. 15 jerseys are 3 labels. A list line is one field with no `^FB` box (`tight` in labels.js): a text wider than its box wraps and the printer prints the wrapped piece over the start of the line ("11-MACDONALD-AXL" came out as "XL-MACDONALD-A", 10 Nov 2026). Text width is estimated letter by letter (`textUnits`: capitals are wide), a long name is squeezed to 70% width before it is made smaller. The list starts 2 mm in from the left edge (`BIN_LIST_LEFT_MM`): the ZD411 cut that much off the left of the 2 × 1 in roll. Finish order prints the list of every bin still open with something in it (the dialog says how many labels). Closed bins can print their list again from the dialog. Switch: Settings → Label printer (`binLists`). An order with one team or size, or not sorted, is one bin, and Bin full works on it the same way.
- Boxes (`src/lib/boxmodel.js`; the owner would not put a hard cap on jerseys per box, 10 Nov 2026): a box is full by room or by weight, whichever comes first. Each jersey takes room by its size class (youth, adult S/M, L/XL, 2XL, 3XL+) and whether the order is stitched or sublimated (`jerseyTypeOf(...).construction`; no type set counts as stitched), in units of one adult 2XL stitched jersey; each box (small, medium, large) holds so many units; weight is the operator's judgement for now (owner, 11 Nov 2026: an experienced operator knows the box; a scale connected to the station PC is a future update), so the weight estimate is off by default (Settings → Packing, `boxWeights`): no lb shown, no warning, no cap. Switched on, each jersey has an estimated weight and no box goes over the cap (`boxWeightCap`, default 45 lb). `predictBox(binCounts(rows, stitched), model)` names the smallest box with the room, or "2 large boxes" past a large box or the cap; a one-piece bin is a bag. The numbers start as estimates (`PRIOR`; only "34 adult 2XL in a large box" and "45–48 lb" came from the floor, the weights are guesses until someone weighs a jersey) and the room numbers are learnt: "Box full" asks "What size is Box 5.1?" (small, medium, large) with the suggestion marked, the answer is kept with the closed box (`box`; not printed on its list), and to the hub (`POST /api/hub/boxes { counts, box, … }`, `state.boxAnswers`, the newest 3000), which fits the model to the newest 600 (`fitBoxModel`) and serves it to every station (`GET /api/hub/boxes`; kept in `localStorage["jerseyqc.boxmodel"]` for when the hub is away). Finish order does not ask and does not teach: its lists carry the suggestion. With the weight estimate on, an open bin at 95% of the cap turns the Bin full button red ("Bin 1 ~45 lb — close it") and its row in the dialog says so. The box shows beside each bin in the Bin full dialog, in its closing message, on the Finish order dialog, and on a "Boxes" sheet of the order's Excel (`buildBinsSheet`). The station reports `closedBins` and `binSummary` in its snapshot, so the board's order view and order sheet show the same. `src/lib/boxes.js` (the flat count) is only the simulation's baseline now.
- Where the screen was (`src/lib/attention.js`): while an order is open the station records away spells — the page hidden (minimised, another tab, locked) or another window in front for 5 s or more (`awaySpells`, `createAwayWatch`) — beside the idle spells IdleWatch already kept (`idleSpells`: screen up, untouched 3 min+). A page can only see that its own window was left, never where the operator went or what was typed; the spells carry no operator name (owner's decision, 9 Nov 2026), only the station and the times. Both go in the saved session, to the hub snapshot (`idle`, `away` on the order record) and onto Excel: an "Attention" sheet on every order export (station and board), and "Idle spells" / "Screen left" columns on the day sheet's Orders tab.
- Lock-down: an operator's station goes full screen on sign-in; `Start Station (kiosk).bat` (or `Jersey QC Station.exe`, built from it by `tools/build-station-exe.ps1` with IExpress; the exe runs the launcher from a temp folder, so the browser is started with `/D %USERPROFILE%` and via `call .station-kiosk.bat`) opens Edge in kiosk mode (no address bar, tabs or menus; Alt+F4 closes it) on the station link, asking for the server address and station once and keeping them in `%APPDATA%\JerseyQC\station.cfg`. A web page cannot lock a browser by itself; a station that must not reach the internet needs the kiosk launcher or Windows kiosk mode / assigned access.
- Result screens are a size container (`containerType: "size"` on the overlay root). The green screen is two halves above the buttons: number, name and team on the left, SIZE and BIN stacked on the right; each column is its own size container and its text is sized in that column's `cqh`/`cqw` (the number shrinks for 3 digits, the name for long names), so the screen fills a 27" station panel and still fits 1080p with the inspection banner, check pills and order notes showing. The by-hand screen's SIZE and BIN boxes use the overlay's units.
- Rate and ETA at the station (`src/lib/pace.js`): from working time, not the clock. The gap between one scan and the next counts in full up to 10 minutes (`CAP_MIN`); a longer gap (a break, a shift end, a night with the order left on screen) counts as 10, and so does the gap from the last scan to now. The hub's board rate is a rolling 20-minute window of its own (hub-plugin.js).
- Big orders (checked for a 500-jersey order, 11 Nov 2026):
  - Saved session (`src/lib/persist.js`): every log entry carries a ~7 KB thumbnail, so 500 scans pass localStorage's ~5 MB by themselves. `sessionBody` drops, in order, the flag photos beyond the newest 20, all flag photos, the thumbnails and model usage figures beyond the newest 60 entries, then all thumbnails; the roster and each entry's match, status, reason and time are always kept. `saveSession` returns false when the write still fails and the header shows a red "NOT SAVING" pill (`saveOk`).
  - Roster table: each row is a memoised `RosterRow` with one shared handler (`onMarkRow`) and a stable column list (`rosterColsStable`); rebuilding 500 rows with a menu each on every render held the screen ~0.75 s. Keep new props to it stable.
  - Hub report (`snapshotOf`): every log event is sent (no 400 cap), and `attention` lists the open items first, up to 100.
  - Hub state file: written to `hub.json.tmp` and renamed; a file that does not parse is renamed aside (`.unreadable-…`) rather than overwritten by an empty hub. The request body is joined as bytes before decoding.
  - Finish order prints the open boxes' lists and keeps the order open on the done screen until "New order": a failed print says so in red there and the lists can be printed again.
  - A row with nothing in the field the order is sorted by (blank team on a by-team order) goes in a "No team" / "No size" bin (`BLANK_KEY`), so every jersey is in a bin. A jersey flagged after its bin was closed leaves that bin (`dropFromClosed` in `chooseReason` / `reasonSubmit`).
  - Labels: every one-line `^FB` field is squeezed (narrower letters) until its text fits, so no label can wrap over itself (`line` in labels.js).
- `exportRosterXLSX()` writes status + all roster columns to Excel; `exportLogCSV()` writes the scan event log
